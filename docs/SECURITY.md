# Безопасность и E2EE

## Принципы

- Сервер не должен иметь доступ к открытому тексту сообщений.
- Сообщения, вложения и голосовые сообщения шифруются на клиенте.
- Аватарки не шифруются.
- Приватные ключи устройств не хранятся на сервере в открытом виде.
- Реальные SMTP-пароли, JWT-секреты и ключи API не коммитятся.

## Учетные данные

Основной пароль используется для входа. Облачный пароль используется для восстановления зашифрованных ключей на новом устройстве.

Если пользователь потерял устройство и забыл облачный пароль, восстановить E2EE-ключи невозможно. Это ожидаемое свойство настоящего сквозного шифрования.

## Личные чаты

1. Клиенты создают пары ключей.
2. Сервер хранит публичные ключи.
3. Отправитель шифрует сообщение для получателя на клиенте.
4. Сервер передает и временно хранит только ciphertext.
5. Получатель расшифровывает сообщение локально.

## Групповые чаты

1. Для группы создается групповой ключ.
2. Групповой ключ шифруется отдельно для каждого участника.
3. Сообщения шифруются групповым ключом.
4. При удалении участника ключ группы обновляется.

## TTL сообщений

Сообщения хранятся не дольше 2 часов. После истечения `expires_at` они удаляются фоновой задачей.
